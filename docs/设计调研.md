# 控制台设计调研（2026-10-16）

> 这份文档是 2026-10-16 前端全面重构的**设计依据**。所有数值都来自一手来源——设计系统的官方文档、
> 官方 token 文件、或直接从生产站点抓取的 CSS——不是印象或转述。文末列了完整来源。
>
> 保留它的目的有两个：一是让「为什么长这样」有据可查；二是让后续改这个项目的 AI 有设计上下文，
> 不至于每次重画一遍。

## 0. 结论摘要

> ### ★ 2026-10-16 第二次变更：由「全灰阶」改为「蓝色科技风」彩色主题
>
> 起因是一句真实反馈：**"这个 ui 一点颜色都没有，看着死气沉沉的"**。
>
> 原方案把中性色全部压在 Radix Slate 上、只把颜色留给状态语义。这个思路在**可用性**上
> 是站得住的（颜色一出现就意味着"看这里"），但在**观感**上确实单薄：整屏都是灰阶，
> 看上去像没做完。这是一次审美层面的主动调整，不是修 bug。
>
> 改版的核心取舍是**按面积分层投放颜色**，而不是到处刷彩色：
>
> | 面积 | 处理 | 例子 |
> |---|---|---|
> | 大（页面底/卡片） | 仍接近白色，只带一点冷蓝 | `--background: #f7f8fc`、`--card: #fff` |
> | 中（顶栏/页头/KPI/选中态） | **品牌蓝**为主，是"有颜色"的主要观感来源 | 导航选中实心蓝、KPI 标签蓝字、页头竖条 |
> | 小（状态点/chip/图表） | 继续**只**表示状态语义，不上装饰色 | danger 红、success 绿、warning 橙 |
>
> 关键结论：
> 1. **主色** `--primary`：`#1c2024`（近黑）→ **`#2563eb`**。白字 5.17:1、作正文 4.87:1，两种用法都过 AA。
> 2. **中性色**：仍是 12 档，但整体向蓝偏移（与品牌蓝同源），不再等同 Radix Slate 的原值。
> 3. **`info` 与 `primary` 复用同一个蓝**（`#2563eb`）。这是有意的：项目里 info 只出现在
>    request-log 的「流式」标记，不会与主色同屏互扰；两套蓝反而会显得脏。
> 4. **新增** `--primary-subtle` / `--primary-border` / `--shadow-primary` / `--gradient-brand`。
>    渐变目前**只剩一个使用点**：页头标题左侧那根 4px 竖条（见下方勘误）。
>    大面积渐变会让文字对比度随位置浮动，无法稳定断言。
> 5. **`region-dot.tsx` 去掉了硬编码的原生色**（`bg-emerald-500/80` / `bg-sky-500/80`），
>    改用 `bg-success-dot` / `bg-info-dot`。那是全项目唯一绕过 token 的色，也是对比度校验的盲区。
> 6. 全部 **55 项对比度断言仍然全绿**，`verify-ui.mjs` 104 项界面断言全绿。
>    这次改版没有靠"放宽标准"来换颜色。
>
> #### ⚠️ 勘误：两条全宽渐变线已按反馈去掉（同日）
>
> 初版还在**顶栏底部**和**KPI 统计条顶部**各加了一条 2px 全宽品牌渐变线。
> 反馈很直接："**蓝色的线条太显眼，有点突兀**"。
>
> 复盘——这两处为什么是错的：
> 1. 它们都是**横贯整个视口宽度的饱和横线**，在横向布局里是最抢眼的形状，
>    权重甚至超过它所在容器的标题与数值。
> 2. 它们**不承载任何信息**，是纯装饰。在同一个界面里，有语义的蓝（导航选中、
>    主按钮）和没语义的蓝（装饰线）混在一起，会稀释"蓝色=可交互/当前"的信号。
> 3. `--gradient-brand` 的亮端接近 `#38bdf8`，比主色更亮，视觉上更"跳"。
>
> 结论：**品牌色只留给有语义的元素**（Logo、导航选中态、按钮、标签文字）。
> 已删除 `.topbar-brand-line`，KPI 条顶线一并移除；页头那根 4px 竖条保留
> （窄、短、贴着标题，不构成"横线"的观感）。
> 这两条都写进了对应组件的注释，避免以后又被"加回去"。
>
> 改动的文件：`web/src/index.css`（token 层）、`app-topbar.tsx`、`page.tsx`、`panel.tsx`、
> `stat-strip.tsx`、`empty-state.tsx`、`region-dot.tsx`、`routes/models.tsx`、`routes/usage.tsx`。

> **2026-10-16 后续变更：面板改为固定浅色，不做主题切换。** 第 5 条「深色」当时的设计与
> 调研结论**仍然完整保留在本文档里**（§2.2 / §2.4 / §2.6 / §2.7），因为它们是
> 「层级为什么该这么做」的知识，且万一以后恢复深色可直接复用；但要清楚：
> **深色目前没有实现**。已移除的东西：`.dark` token 层、主题 hook、
> `dashboard.html` 的预绘制脚本、顶栏与命令面板的切换入口、深色截图、深色对比度断言。
> 要恢复就先看 `web/scripts/check-contrast.mjs` 顶部那段守卫，它列了需要一并恢复的清单。

1. **选型**：shadcn/ui + Tailwind CSS v4 + Vite。理由是 AI coding 友好度（组件是仓库里的源码、官方有 Skills 与 MCP server）与视觉上限（可完全对齐 Vercel Geist）。
2. **中性色**：12 档冷灰（向蓝偏移，见上方改版说明）。每档用途固定，且对比度经程序化实测。
3. **字体**：拉丁与数字用 Geist，中文回落系统字体（苹方）。**不内嵌任何 CJK webfont**，理由见 §4。
4. **材质**：用 Geist 的「阴影描边」`0 0 0 1px` 代替 `border`，不占布局、贴合圆角。
5. **深色**：不用纯黑，层级靠**表面明度**而非阴影。→ ⚠️ **已移除，见上方说明**。
6. **一条硬约束**：字号与行高取**偶数**（Grafana 在代码里断言这条），这是「看起来对齐」的物理保证。
7. **配色**：品牌蓝 `#2563eb` 作主色；颜色按**面积**分层投放（见上方表格），状态色严格只表示状态。
8. **数据展示**：不搞"全表格"也不搞"全图形"，**按读者要回答的问题选形状**。
   `chart-*` 是离散序列色（靠色相区分"哪个指标"），
   `chart-gradient-*` / `chart-heat-*` 是连续量级色（靠明度区分"多少"）。
   两类色阶的验收标准不同：前者对背景 ≥3:1，后者验收**相邻档** ≥1.28:1。
   依据与实测见 [可视化方案调研.md](可视化方案调研.md)。

## 0.1 数据展示的选型规则（2026-10-16 新增）

改版起因是一句反馈："现在的项目全部都是表格，一方面信息密度低另一方面不够美观"。
调研后的结论**不是"表格不好"**，而是三个具体问题，以及由此归纳出的选型规则：

| 数据形态 | 该用什么 | 为什么 | 项目里的落地 |
|---|---|---|---|
| 可枚举属性（区域、倍率、是否免费） | 徽章 / 圆点 | 只回答"是哪个"，不需要列对齐 | 模型页卡片、状态点 |
| 可比的单一量（余额、请求占比） | 横向条 | 长度比数字更快被扫读，且能提前预警 | 账号行余额、按模型表占比 |
| **分布**（延迟、大小） | 分布条 / 带状图 | 两个数字（平均+最慢）并列时读者无法判断"是常态还是事故" | 按模型表延迟分布 |
| **时间序列，稠密** | 折线 / 柱状 | 连续性本身就是重点 | 用量区块「每日走势」（柱=请求 + 线=tokens） |
| **时间序列，稀疏** | 日历热力图 | 90 天里 89 天为零时，柱状图会画出 89 根零高柱子，看起来像坏了 | （当前数据不稀疏，暂不需要） |
| **行内趋势**（每行的历史） | 迷你条 | 表格每行只能表达"当前值" | 按模型表趋势列 |
| 需要**逐行比对**或**可复制 ID** | **保留表格** | 列对齐与复制边界不可替代 | 按模型表、最近请求日志 |
| 身份 + 一个结论（账号面板） | **grid 列表，4 字段封顶** | 表格的列头是重复的双重成本、逐行间距又压不下去；卡片则每个账号重复一遍标签 | 账号面板（2026-10-16 起） |

三条必须记住的教训（都是这次踩出来的）：

1. **日历图不能跟着统计窗口缩放**。最初写成 `slice(-weeks*7)`，
   "近 7 天"窗口只画出 7 个格子 —— 一排孤立方块看起来像渲染出错。
   日历的阅读方式是"扫一片颜色找规律"，少于 4~5 周就没有规律可言。
   **正确做法：网格固定铺满 weeks 周，数据不足处留空位**，保证切窗口时尺寸稳定。
   （后来「每日走势」改回柱+线，但这条规则仍然适用于任何日历形态。）

2. **绝对不要为了"更可视化"去替换表单**。签到表曾是 checkbox + 批量 + 二次确认，
   那是**表单**不是数据展示。把它改成图形是倒退，不是进步。
   ⚠️ 2026-10-16 晚的补充：这条规则**没有被推翻，是被"消灭了适用对象"**——
   用户要求签到改为服务端全自动，那个表单因此整个被删除，而不是被改成图形。
   剩下的「是否签到」是一个只读结论，用一行 `StatusLabel` 表达。
   **所以这条规则仍然是规则**：只要还存在着需要用户"填"的东西，就不要把它画成图。
   结论：是**把表单去掉**，不是**把表单画出来**。

3. **连续色阶的颜色验收标准和离散色不同**。
   照搬 3:1 会逼出极深的配色，整片热力图会糊成一块。
   连续色阶是"格子挨着格子"被比较的，所以验收**相邻档**比值。
   这条已经写进 `check-contrast.mjs` 的 `adjacent` 级别。

**「AI coding 友好」的具体机制**（不是形容词）：

- `skills add shadcn/ui` 把 skill 装进项目。之后 AI 每次自动跑 `shadcn info --json` 读你的 `components.json`（框架、别名、已装组件、icon 库、base 库），再按官方 composition 规则生成代码。
- `.mcp.json` 配 `npx shadcn mcp`，AI 可直接检索/安装 registry 组件。
- `shadcn search` / `docs` / `view` / `diff` 让 AI 先查文档再落笔。
- 组件以源码形式落在 `src/components/ui/`，AI 能读能改，不必跟 `node_modules` 搏斗。

## 2. 确切 token

### 2.1 Vercel Geist 的真实 CSS 变量

从 vercel.com 生产 CSS chunk 中提取。

**间距（4px 基数，命名即倍数）**

| Token | 值 |
|---|---|
| `--geist-space` | 4px |
| `--geist-space-2x` | 8px |
| `--geist-space-3x` | 12px |
| `--geist-space-4x` | 16px |
| `--geist-space-6x` | 24px |
| `--geist-space-8x` | 32px |
| `--geist-space-10x` | 40px |
| `--geist-space-16x` | 64px |
| `--geist-space-gap` | 24px |
| `--geist-space-small / medium / large` | **32 / 36 / 40px —— 控件高度** |

> 控件高度是 token，不是用 padding 凑出来的。这是「看起来专业」的隐形来源：所有输入框、按钮、Select 同高，行永远对齐。

**圆角**：`--geist-radius: 6px`（UI 默认）· `--geist-marketing-radius: 8px`

**阴影 —— 关键洞察：边框被做成了阴影的一部分**

```css
/* 亮色 */
--ds-shadow-border-base: 0 0 0 1px #00000014;        /* ≈ 8% 黑 */
--ds-shadow-2xs: 0px 1px 1px #0000000a;
--ds-shadow-xs:  0px 1px 2px #0000000a;
--ds-shadow-small: 0px 2px 2px #0000000a;
--ds-shadow-medium: 0px 2px 2px #0000000a, 0px 8px 8px -8px #0000000a;
--ds-shadow-large:  0px 2px 2px #0000000a, 0px 8px 16px -4px #0000000a;
/* 暗色：描边变成白色微光 */
--ds-shadow-border-base: 0 0 0 1px #ffffff25;        /* ≈ 14.5% 白 */
```

> `0 0 0 1px` 的**「阴影描边」代替 border**：不占布局空间（不会因为 1px 边框产生 2px 的尺寸抖动），且能跟圆角完美贴合。用于卡片、表格容器、下拉菜单。

**动效**

| Token | 值 |
|---|---|
| `--ds-motion-timing-swift` | `cubic-bezier(.175, .885, .32, 1.1)` |
| `--ds-motion-popover-duration` | `0.2s` |
| `--ds-motion-overlay-duration` | `0.3s` |
| `--ds-motion-overlay-scale` | `0.96` |
| 焦点环 | `0 0 0 2px var(--ds-background-100), 0 0 0 4px var(--ds-focus-color)` |
| 等宽数字 | `.geist-tabular-nums { font-feature-settings: "tnum" }` |

> **焦点环 = 2px 背景色隔离环 + 2px 强调色外环**。在任何背景上都可见，且满足 WCAG 2.4.13。

**排版刻度（Geist 官方 class 与用途）**

| 类名 | 用途（官方描述） |
|---|---|
| `text-heading-72/64/56/48/40/32/24/20/16/14` | 页面或区块标题，逐级递减 |
| `text-button-16` | 最大按钮 |
| `text-button-14` | **默认按钮** |
| `text-button-12` | 仅用于输入框内的小按钮 |
| `text-label-16` | 标题，加 Strong 区分 |
| `text-label-14` | **全系统最常用字号** —— 菜单、表格、正文标签 |
| `text-label-13` | 带 Strong + **Tabular**；次要行。**数字必须 tabular** |
| `text-label-12` | 拥挤视图的三级文字 |
| `text-copy-14` | 最常用连续文本 |
| `text-copy-13` | 空间紧张时的次要文本 |

遗留 CSS 的确切值：`.h6 { font-size:.875rem; font-weight:600; letter-spacing:-.005625rem }` ·
`.label { font-size:12px; font-weight:500 }` · `.small { font-size:14px }` · `.p { line-height:1.6 }`

> **Geist 官方明确区分 `Label` 与 `Copy`**：Label 是单行、行高较紧（配合图标与数字对齐）；Copy 是多行、行高 1.6。
> 控制台 90% 的文字是 Label。**不要用 1.6 的行高渲染表格里的单行文本**，那会白费垂直空间。

### 2.2 Geist 的语义色彩分层

官方对每一档的分工（与 Radix 12 步几乎一一对应）：

| Geist 角色 | 用途 |
|---|---|
| Background 1 / 2 | 页面底 / 次级底 |
| Color 1 / 2 / 3 | 组件默认底 / hover / active |
| Color 4 / 5 / 6 | 默认边框 / hover 边框 / active 边框 |
| Color 7 / 8 | 高对比实心底 / hover |
| Color 9 / 10 | **次级文字与图标 / 主文字与图标** |

### 2.3 Radix 12 步的用途契约

官方表格：

| Step | 用途 |
|---|---|
| 1 | 应用背景 |
| 2 | 次级背景（**斑马纹表格**、代码块、卡片、侧栏） |
| 3 | 组件默认背景 |
| 4 | hover 的组件背景 |
| 5 | active / 选中 的组件背景 |
| 6 | **细边框与分隔线（非交互组件）** |
| 7 | **交互组件边框 + 焦点环** |
| 8 | hover 边框 |
| 9 | 实心块背景（最高彩度） |
| 10 | hover 实心块 |
| 11 | **低对比文字** |
| 12 | **高对比文字** |

官方保证：**「Steps 11 and 12 …… 在同色阶的 step 2 背景上分别达到 Lc 60 与 Lc 90 的 APCA 对比度」**。

⚠️ 官方特别警告：**Sky / Mint / Lime / Yellow / Amber 的 step 9 是为深色前景文字设计的**，配白字会失败 —— 我们的实测证实了这一点（见 §2.5）。

> **永远不要混用色阶的档位**（例如拿 gray-3 当边框、gray-9 当普通文字）。这是「业余感」最常见的技术与审美双重错误。

### 2.4 Radix Slate 12 档（本项目选定的中性色）

> ★ **改版提示**：下表是 Radix Slate 的原始值（调研记录）。2026-10-16 彩色改版后，
> 本项目的 12 档中性色**整体向蓝偏移**，以便与品牌蓝 `#2563eb` 同源。
> 真正生效的值见 `web/src/index.css` 的 `:root`（`--slate-1` … `--slate-12`）。
> 用途契约（1-2 底 / 3-5 组件底 / 6-8 边框 / 9-10 实心 / 11-12 文字）**完全不变**。

| 档 | 用途 | 亮色 | 暗色 |
|---|---|---|---|
| 1 | 应用背景 | `#fcfcfd` | `#111113` |
| 2 | 次级背景 / 侧栏 / 代码块 | `#f9f9fb` | `#18191b` |
| 3 | 组件底 | `#f0f0f3` | `#212225` |
| 4 | hover 底 | `#e8e8ec` | `#272a2d` |
| 5 | active / 选中底 | `#e0e1e6` | `#2e3135` |
| 6 | 细边框 / 分隔线 | `#d9d9e0` | `#363a3f` |
| 7 | 交互边框 / 焦点环 | `#cdced6` | `#43484e` |
| 8 | hover 边框 | `#b9bbc6` | `#5a6169` |
| 9 | 实心块 / 禁用文字 | `#8b8d98` | `#696e77` |
| 10 | hover 实心块 | `#80838d` | `#777b84` |
| 11 | **次级文字** | `#60646c` | `#b0b4ba` |
| 12 | **主文字** | `#1c2024` | `#edeef0` |

**P3 变体**（Radix 官方写法：hex 为默认值，P3 包在 `@supports` 内做渐进增强）：

```css
:root { --slate-11: #60646c; --slate-12: #1c2024; }
@supports (color: color(display-p3 1 1 1)) {
  :root {
    --slate-11: color(display-p3 0.379 0.392 0.421);
    --slate-12: color(display-p3 0.113 0.125 0.14);
  }
```

**边框与文字用 alpha 派生，不用固定灰**：

```ts
// 暗色

border = { weak:   rgba(whiteBase, 0.12),        // 装饰性
           medium: rgba(whiteBase, 0.20),        // 组件边框
           strong: rgba(whiteBase, 0.30) };      // 激活 / 聚焦
text   = { primary: rgb(whiteBase),
           secondary: rgba(whiteBase, 0.65) };
// 亮色对称
border = { weak: rgba(black, 0.12), medium: rgba(black, 0.30), strong: rgba(black, 0.40) };
```

> 这跟 Vercel 的 `#ffffff25`（≈14.5%）/ `#00000014`（≈8%）高度一致 ——
> **两个独立的大型设计系统都收敛到「约 12%–20% 的白色 / 8%–14% 的黑色」**。这就是该用的数字。

**圆角**：`sm 4px` · `default/md 6px` · `lg 10px` · `pill 9999px`
**间距**：`x0_25=2` · `x0_5=4` · `x1=8` · `x1_5=12` · `x2=16` · `x3=24` · `x4=32` · `x5=40` · `x6=48` · `x8=64`

## 4. 中文字体：为什么**不**内嵌 CJK webfont

### 4.1 Geist / Inter 没有中文字形

Vercel 的字体栈是 `"Geist", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", "Roboto", ...`
—— 全是拉丁字体。浏览器按 MDN 明确说明的规则工作：*"font selection is done one character at a
time, so that if an available font does not have a glyph for a needed character, the latter fonts
are tried"*。

**所以中文界面上 Geist 只渲染拉丁字母与数字，中文靠后面的系统字体回落。这不是缺陷，是正确用法**：
拉丁与数字用精心设计的字体（更精确），中文用系统 UI 字体（渲染质量最高、零下载）。

### 4.2 硬数据

| 事实 | 数据 |
|---|---|
| Noto Sans SC 三字重被切成 | **303 个 `@font-face` 块**（3 × 约 101 片） |
| 完整载荷投影 | **约 4.78 MB** |
| `@fontsource/noto-sans-sc` 解压体积 | **74.6 MB** |
| 中文字符集规模 | 常用 3,500 / GB 2312 6,763 / GB 18030 逾 27,000 字（拉丁字母约 230 字形） |

4. 个不内嵌的理由：

1. **离线是硬约束**。切片（`unicode-range`）的收益来自按需网络请求；一旦离线就必须全部预置，退化为下载整个 4.78MB。
2. **自己子集化会让动态数据渲染不一致**。把 UI 固定文案抽成子集能压到 50–150KB，但模型名、错误信息里会出现子集外的字，同一行字重/字形突变，非常明显。
3. **布局抖动（CLS）**。CJK webfont 与 fallback 的行高、基线有差异。`font-display` 的 swap 会造成可见跳变，block/optional 则首屏显示 fallback（同样跳变）。对本地工具，**永不跳变**才是高级。
4. **系统字体质量本就顶级**。苹方（PingFang SC）与微软雅黑就是为屏幕优化的 UI 字体。省下的 5MB 花在 token 与状态设计上，收益大得多。

### 4.3 字体栈与排序原则

```css
--font-sans: "Geist Variable", system-ui, -apple-system,
             "PingFang SC", "Hiragino Sans GB",
             "Microsoft YaHei UI", "Microsoft YaHei",
             "Noto Sans CJK SC", "Source Han Sans SC", "WenQuanYi Micro Hei",
             sans-serif, "Apple Color Emoji", "Segoe UI Emoji";
```

- 中文必须放在拉丁之后（否则拉丁字母会走中文字体的拉丁字形，质量差）
- `sans-serif` 泛型必须放在最后（MDN：没有任何字体可用时要有兜底）
- Geist 走 `@fontsource-variable/geist`（npm 包，**非 CDN**），浏览器只实际下载 latin 子集 **29KB**

### 4.4 `tabular-nums` 的用法

**这是对「专业感」影响最大、却最容易被忽略的一条。**

问题：比例数字中 `1` 比 `8` 窄，所以 `1,284` / `1,384` / `1,184` 三行纵向看参差不齐。

```css
.tnum, td.num, .kpi-value, time, .id {
  font-variant-numeric: tabular-nums;
  font-feature-settings: "tnum";     /* 兼容旧语法，Geist 用的就是这个 */
}
```

**必须加**：KPI 主数值（**轮询刷新时数字宽度不变，不会左右跳动——这是最关键的收益**）、
表格所有数字列、时间戳、模型上下文、图表 Y 轴刻度与 tooltip 数值、百分比、uptime、计数徽标。

**不要加**：正文段落、中文标题、大段中文说明（那里比例数字更好看）。

>
> 早期版本这里写的是「首屏 531 KB」，那个数字来源已不可考、且与产物对不上，已替换成实测值。
> 教训：**体积这类数字要么留一条可复现的命令，要么就不要写在文档里** ——
> 否则它会在某次改动后静静变成谎言，而没人能判断它错在哪。
>
> 另一条同类教训：**不要用 chunk 文件名推断内容**。Rolldown 给自动切出的共享 chunk
> 命名时取其中一个成员模块，于是 `clipboard-*.js` 里一条 clipboard 代码都没有
> （装的是 sonner + TanStack Query + cn），而 ReactDOM 在主入口 chunk 里。
> 我们真的据此错记过一次，这也是 `analyze-bundle.mjs` 存在的原因。

两条实测得到的结论，都可执行：

1. **别用 `typescript` 语法去高亮没有类型标注的代码。**
   本项目的 Node 片段是 `import` / `const` / `await` / `for await`，
   一个类型标注都没有 —— 用 `javascript` 语法得到的高亮**完全一样**，
   却省掉 181 KB。所以 `language`（给用户看的文件类型提示）和
   `highlightAs`（真正的高亮语法）在代码里是**两个独立参数**。
2. **接上的懒加载是可以退化的，得有断言盯着。**
   `verify-ui.mjs` 里有两条：首屏不得请求任何语法 chunk；
   进接入页后必须请求到它们。否则某天有人把 `import()` 改成静态 `import`，
   首屏悄悄胖 463 KB 而没人发现。

若接入页的体积成为问题，本节的兜底方案仍然有效：退到 Prism（core 6.96 KB + 1.08 KB/语言，
三种语言约 10 KB gzip），或改服务端预高亮（运行时 0 KB）。**不要**退回手写正则。

**token 配色（固定浅色，与整体体系一致）**：

```css
:root {
  --code-bg: var(--slate-2);
  --tok-kw: #0d74ce;   --tok-str: #218358;  --tok-num: #ab6400;
  --tok-com: #60646c;  --tok-fn: #7c2ea3;   --tok-punct: #1c2024;
}
```

> 面板固定浅色，不做主题切换，所以没有 `.dark` 覆盖。曾经有过一组深色值
> （kw `#70b8ff` / str `#3dd68c` / num `#ffca16` / com `#b0b4ba` /
> fn `#d4a0ff` / punct `#edeef0`），随主题切换一并移除了。

紫 `#7c2ea3` 取自 Grafana 的 `purpleLightText`，保证风格统一。

**实现方式：让 shiki 直接把颜色输出成 `var(--tok-*)`。**

shiki 只是把 theme 里的颜色字符串原样写进 inline style，**不校验也不归一化**颜色格式
（已实测）。所以可以把 CSS 变量当颜色喂给它：

```ts
settings: [{ scope: ['keyword'], settings: { foreground: 'var(--tok-kw)' } }]
```

于是渲染出来是 `<span style="color:var(--tok-kw)">def</span>`，好处是：

- **色表与全站 token 同源，且只此一份** —— 不在 TS 里再抄一份十六进制色表，
  两边慢慢写飘的问题从根上没有了。改配色只动 CSS，`highlighter.ts` 一行不用改
  （万一以后恢复深色主题，也只需给 `.dark` 覆盖 `--tok-*`，
  不需要官方双主题那套 `--shiki-light` / `--shiki-dark` 胶水代码）；
- 输出仍然是**真的 React 元素**（`codeToTokens` → `<span>`），
  不需要 `dangerouslySetInnerHTML` 注入 HTML 字符串。

**绝对不要**：深色底 + 霓虹语法色（2015 年主题）；用与整体 token 无关的孤岛色（如 `#282c34`）。

## 6. 复制交互与剪贴板

```js
async function copyText(text) {
  if (navigator.clipboard && window.isSecureContext) return navigator.clipboard.writeText(text);
  // 回退：http://127.0.0.1 在 Chrome/Firefox 算 secure context，
  // 但用局域网 IP 访问就不算 —— 所以这个回退不是可选项
  const ta = document.createElement('textarea');
  ta.value = text; ta.setAttribute('readonly', '');
  ta.style.cssText = 'position:fixed;top:-1000px;opacity:0';
  document.body.appendChild(ta); ta.select();
  document.execCommand('copy'); ta.remove();
}
```

- 反馈**就地**（按钮本体变对勾，150ms 换、停 1200ms、150ms 淡回），不要用全局 toast —— 局部反馈不需要用户移动视线
- 整块可点击复制时用 `cursor: copy`（浏览器原生语义，比 `pointer` 准确）
- 键盘等价：元素需 `tabindex="0"` 且 Enter / Space 可触发
