除了表格，还能怎么展示？

每一种方案都用本机真实数据渲染（3 个账号 / 5 个模型 / 90 天走势 / 200 条日志），并就同一条信息与表格做并排对比。 绿色 = 建议采用，橙色 = 有条件采用，灰色 = 不推荐。

1 · 分布条替换"最慢/平均"两列 建议采用

聚合表里同时放了 平均延时 和 最慢。这两个数放一起会误导： 平均 3.7 秒、最慢 143 秒（一个 4xx 卡了 2 分多钟）——读者无从判断"慢"是常态还是个别事故。 换成一条 20 格的分布条，形状立刻说明问题：左侧一坨实心 + 右侧一条长尾。 表格里要表达同样信息需要 2 列 4 个数字，且仍然读不出形状。

2 · 日历热力图替换 90 根柱子 建议采用

关键发现：90 天的数据里 只有 1 天有流量。柱状图会画出 89 根零高柱子 —— 一张几乎全空的坐标系，还被描述成"按日聚合，共 90 天"。日历热力图把 90 天压进 13×7 的方格，空白本身就是最有信息量的一笔："这是个新池子 / 数据才落盘"， 而不是"图表坏了"。同屏还能顺带表达星期几的规律。

3 · 横向条替换"额度耗尽"这类布尔列 建议采用

账号表里"可用 / 额度耗尽 / 冷却中"是三态布尔：表格必须用一列，而这一列 3 行有 2 行都在说"没事"。横向条（实际消耗 / 余额，剩下多少一眼可见）把 状态和量级合并到同一笔：绿条长度 = 还能用多久，红条 = 已经打满了。 比"额度耗尽"三个字早得多就能预警。

长度 = 剩余，尾段 = 本会话消耗

失败构成

4 · 状态点阵替换"可用 N/M" 有条件采用

"可用 3/3" 是 5 个字符，点阵是 3 个方块 —— 字符更少但面积更大。 它的价值在账号数变多时体现：50 个账号时 "41/50" 完全无法定位是哪些坏了， 而 50 个色块能一眼看出散布的坏点。代价是占用垂直空间。账号数 < 8 时不必上。

5 · 延迟带状图（对照柱状图） 按需采用

柱状图适合"次数"这类可加的度量；延迟不能相加。用柱子画平均延迟， 读者会下意识以为"柱子高 = 请求多"。带状图（中位 + 四分位 + 极值须）形状上就说明 这是分布不是累计量。下方左右对比同一份数据。

6 · 行内趋势线 / 迷你条 建议采用

8 · 圆弧（环形进度） 不推荐

项目里没有"目标值 vs 当前值"这类比例型指标，而圆弧的唯一强项就是表达 "完成了百分之多少"。没有分母时圆弧只是在浪费面积：它比数字大 20 倍， 却只承载 2 位有效数字。列在这里是为了明确否决，避免以后有人再提议。
